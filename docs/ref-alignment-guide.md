# Chimera Client：上游参考对齐与批量迁移指南

本指南细化 [AGENTS.md](../AGENTS.md) 与 [AI 治理规范](ai-development-governance.md) 的上游迁移规则。

## 1. 基线、参考与目标

本项目是 Rust 原生代理核心，不是 Chimera Desktop。每轮先核对本仓库当前 `master`、目标任务分支，以及 3 个 Git 子模块的 **gitlink SHA 和目录状态**：

| 参考目录      | 角色                           | 特别注意                                                    |
| ------------- | ------------------------------ | ----------------------------------------------------------- |
| `ref/`        | clash-rs 的 Rust 架构/协议参考 | 相关 crate、API、feature、锁文件可能与 Chimera Client 不同  |
| `ref-mihomo/` | Go 语言 Mihomo 行为参考        | 用于验证网络协议/兼容性语义，不是可直接复制编译的 Rust 源码 |
| `ref-meow/`   | meow-rs Rust 参考              | 核对同一协议/配置的不同实现，不假定其接口和许可与本地一致   |

这些目录通常为只读参照，不主动更改 gitlink 或更新到远端最新。如果参考代码尚未初始化，记录限制并按允许的方式读取固定版本；不能推测上游实现。

**没有人为设置“每次最多复制几个文件/多少行”的上限。** 对互相依赖的协议、transport、DNS、路由、TUN 或配置解析实现，可以先大范围复制完整目录/文件、类型/调用链、测试和资源，再统一替换品牌名并连接本地系统。规模取决于完整性和可验证性，而不是任意较小 diff。

## 2. 迁移前确认调用链

1. 目标行为/可复现问题：协议名称、配置输入、期望网络输出及失败条件。
2. 参考代码：锁定具体 SHA、源文件、类型/符号、必要依赖与 License/NOTICE；对 Rust/Go 区别单独标注。
3. 本地对应：`clash-lib/src/config/`、`app/`、`proxy/`、`clash-dns/`、`clash-netstack/`、`clash-bin/`、Controller API 与 Dashboard 的实际接线。
4. 保留扩展：Chimera 品牌、既有命令行、旧 YAML 字段、HTTP/WebSocket wire、DNS/fake-IP 缓存、网卡/路由保护、热重载、平台兼容和 Cargo feature。
5. 风险及验证：是否会改用户配置、接管 TUN/系统 DNS、暴露 Controller API、使用凭据或连接真实网络；先选隔离的测试和恢复方案。

## 3. 大范围复制，再统一进行品牌映射

1. 在得到任务授权和确认许可后，复制**关联的完整模块**：不仅复制成功路径，也包含错误处理、超时、取消、状态持久化、文件权限、feature 配置、测试和必要资源。
2. 准备审查过的**品牌映射白名单**（源文字、目标文字、允许的文件集合、每一条替换理由）。例如将源码文档或内部应用名称中的上游品牌更改为 Chimera Client；保留第三方协议/许可证中原有的品牌归属。
3. 可以使用受作用域限制的批量脚本替换；**禁止在整个仓库执行无审查的全局 replace**。逐项核查命中结果：Rust 类型名、模块导入、日志、配置文件路径、文档、构建资产以及 Windows/macOS/Linux 的二进制名称。
4. **不能机械替换外部契约**：Clash/Mihomo 的 JSON/YAML wire key、HTTP Controller route、用户配置字段、CLI flags、环境变量、下载域名、第三方软件 ID、加密协商字符串、配置序列化、持久化键值及原有 License/Copyright/NOTICE。如确需改名，单独实现兼容迁移并验证旧消费者。
5. 对 Rust workspace 列出 Cargo 依赖、feature 转发、`#[cfg]` 和目标平台范围；Go 参考仅用于对照语义，不把 Go 源码当作直接可构建 Rust 的证明。
6. 核对完整迁移的“输入 → 解析 → 运行 → 输出/回滚”闭环；不要留下同一个接口的半新半旧实现。没有覆盖的调用方需记录待办和风险，不能声称全部迁移完成。
7. 审查最终 diff、残留上游品牌、命中白名单、许可说明和引用的上游 SHA。优先运行旧实现可失败/新实现可通过的回归、Cargo feature 矩阵和受影响平台相关测试。

## 4. 最重要的回归边界

- **协议与传输**：握手、认证、加密、重试、DNS、TCP/UDP、IPv4/IPv6、超时/取消和半关闭；不要靠一个连接成功声称协议已完全一致。
- **配置**：原始 YAML → 内部配置 → runtime，验证缺省值、旧字段、非法值、错误诊断与热重载；不能用新格式强制覆盖旧用户数据。
- **网络权限**：TUN、路由、系统 DNS、SO_MARK、虚拟网卡及权限状态；真实系统副作用只能在明确批准的隔离环境运行。
- **Controller API**：HTTP Bearer、WebSocket token、CORS、OPTIONS、公开/受限路由和 Dashboard 调用方；不能因为“品牌替换”破坏外部客户端契约。
- **feature 和平台**：支持的最小 feature、单项能力、默认、典型组合及全功能；Android/Windows/macOS/Linux 差异和未测目标必须如实登记。
- **版权许可**：源代码引用必须保留要求的作者、LICENSE 和 NOTICE；不得自行判断所有上游的许可完全相同。

## 5. PR/复盘记录

使用 [AI Issue 模板](../.github/ISSUE_TEMPLATE/ai-task.md) 和 [PR 模板](../.github/PULL_REQUEST_TEMPLATE.md) 记录：

- 本地/参考固定 SHA；复制的目录/文件/相关测试；映射规则白名单与命中审查。
- 本地保留的扩展、必要偏差和不能替换的兼容字段；版权/许可核对结果。
- 测试命令、实际执行数量、验证平台、失败/跳过/未运行的理由。
- 有待完成的调用方、升级/数据迁移条件、回滚路径、Reviewer 与审批结果。

迁移可以大，但**验收必须真实**。本规范不修改任何既有上游子模块或自动引入代码。
